# 管理后台前端设计规范

> 用 `design-taste-frontend`（app screen 流程）定下来的，2026-10-31。风格是 Framed sheet（浅色外框 + 白纸），沿用现有的
> Vite / React / Tailwind / shadcn/ui 和 Geist 字体，不换技术栈。颜色和尺寸都在 [web/src/index.css](../web/src/index.css) 里，
> 公共组件在 [web/src/components/](../web/src/components/)。新页面先照这里做，不为一个页面另起一套风格。

这个后台是一个人自己用的工作台：每天打开好几次，看商品卖得怎么样、订单要不要处理、买家有没有发消息。
所以要的是信息清楚、操作少一步、各页长得一样，不要装饰。

**只在电脑上用，只适配 PC。** 按 1280–1920px 宽的浏览器窗口设计和检查，不做手机布局。
第一轮做过一些窄屏处理（窗口窄于 1024px 时侧栏变顶栏、768px 以下表格变列表、筛选卡片变小标签），代码还在，
但不再维护，新页面也不用做。

## 整体框架

- **外框和白纸**：侧栏放在一块浅石色的外框（`--frame`）上，内容放在外框上的一张白纸（`--background`）上，
  白纸离窗口上、右、下各 8px，16px 圆角，1px 边，没有阴影。侧栏和白纸之间不画线，靠底色差分开。
- **侧栏** 228px：最上面是标志和"闲鱼管理"，下面是**当前账号**（头像、昵称、登录态，点开切换账号、添加账号、去账号矩阵），
  再下面是导航：当前账号的几页（商品、发布、订单、消息、搜索），隔开一点是不分账号的"账号矩阵"和"拼多多货源"；
  最底下是登录的用户（菜单里改密码、插件令牌、退出登录）和切换深浅色。选中的导航项是一块中性灰，不用品牌色。
- **登录页**：外框底色上居中一张 360px 宽的白纸（和内容区同样的 16px 圆角、1px 边），里面是标志、h1"登录"、
  用户名和密码、一个主按钮；没有注册入口，纸下面一句小字说找管理员建。
- 内容区最宽 1200px，在白纸里居中，左右留白 24px。页面里各块之间统一隔 24px。

## 颜色

一个底、一个墨色、一个品牌色。颜色只用在数据、状态和唯一的主操作上，界面框架本身是灰的。

| 用途 | 浅色 | 深色 | 说明 |
|---|---|---|---|
| 外框 `--frame` | `#f5f5f2` | `#0a0a0a` | 带一点暖的石色，不是米黄 |
| 白纸、面板 `--background` `--card` | `#ffffff` | `#141414` | |
| 正文 `--foreground` | `#111111` | `#f5f5f5` | 正文一律用这个，不用灰字写正文 |
| 次要文字 `--muted-foreground` | `#5f5f5b` | `#a8a8a8` | 在白纸和外框上都过 4.5:1 |
| 面板边 `--border` | `#e8e8e4` | `#262626` | |
| 表格行线 `--rule` | `#f0f0ec` | `#1f1f1f` | 比面板边浅一档 |
| 输入框边 `--input` | `#d4d4cf` | `#3a3a3a` | 比面板边深一档 |
| 主按钮 `--primary` | `#1d1f20` | `#f5f5f5` | 近黑，不用品牌色 |
| 闲鱼黄 `--brand` | `#ffe60f` | `#ffe60f` | 字一律用 `#111` |

**闲鱼黄只用在三个地方**：标志、选中的计数筛选卡片、自己发出的聊天气泡。不用在按钮、导航、链接、标题上。

状态色成对用（浅底 + 同色系深字），见下面的"状态标签"。红色只给真正出问题的东西（失败、退款、登录失效），
一个对象上最多一个红色标记。

## 字

- 字体：Geist（数字、英文、ID）+ 系统中文字体（PingFang SC 等）。不加第二种字体；ID、订单号用等宽字。
- 字号只用这几档：

| 用途 | 字号 | 字重 |
|---|---|---|
| 页面标题 h1 | 22px | 600 |
| 块标题 h2、计数卡片的数 | 16px | 600 |
| 正文、表格、按钮 | 14px | 400 / 500 |
| 计数卡片的名字、会话预览 | 13px | 400 |
| 说明、表头、时间、ID | 12px | 400 |
| 小标签里的数 | 11px | 500，最小就到 11px |

- 金额、数量、时间一律 `tabular-nums`，在表格里右对齐。
- 句子写法，不用全大写、不加字间距。

## 圆角

一层套一层往小走，只用这几档：白纸 16px → 面板、卡片 10px → 按钮、输入框 8px → 小按钮、菜单项 6px → 缩略图 6px。
状态标签是全圆角。

## 页面结构

每个列表页都是同一个顺序，从上到下：

1. **标题行**（`PageHeader`）：左边 h1 和一句说明，右边是这一页要用的操作。说明写**数据**，不写界面怎么用：
   "主页上的商品 · 上次同步 3天前"、"2 笔待发货，要到闲鱼 App 里发货 · 近 30 天成交 ¥231"。
   最要紧的那件事（比如有待发货）写在说明最前面。主按钮一页最多一个。
2. **计数筛选卡片**（`CountFilter`）：每种状态一张卡片，上面是名字，下面是数量；点哪张，下面的列表就只显示哪一类。
   选中的那张填闲鱼黄。数量就在卡片上，**不再另做一排 KPI 卡片**重复同样的数。卡片平分整行。
3. **列表面板**：顶上一行是搜索框（搜索时右边显示"1 / 7 件"），下面是表格。
4. **其他块**（`Section`）：比如"最近的改动"，标题放在面板外面，右边一句小字说明。

账号矩阵页也是这个顺序：计数卡片按"全部 / 登录要处理 / 有待发货 / 有未读消息"筛账号，表格一行一个账号
（头像 40px 是圆的，人；商品图才是方的），在售、待发货、未读的数字能点，点了切到那个账号、打开对应的页面。
账号矩阵管的是所有账号，页面顶部不放当前账号的登录、熔断提示，没有账号时也能进。

消息页是两栏：左边会话列表（搜索、全部/未读下划线标签、会话），右边聊天记录，整块撑满一屏、各自滚动。
自己发的消息左边底下一行 12px 小字标对方读没读：已读灰字，未读用 `warning` 的深琥珀字（在等对方）。

## 表格

- 表头 12px 灰字、正常字重，不加底色、不加粗；表头下面一条 `--border`，行之间是更浅的 `--rule`。不做斑马纹。
- 第一列（商品）占最宽，缩略图 48px + 两行：标题（最多两行）和 ID（12px 等宽灰字）。点这一格看详情。
- 金额、数量右对齐；只有商品名和关键数字（价格、金额）用墨色，买家、时间这些用灰色。
- 缺的值显示 `-`，真正的 0 显示 `0`。
- 行操作：要常用的那个直接放出来（"改价"，描边小按钮），其他收进最右边的 `…` 菜单，删除放菜单最后、红字。
- 多于一行时最后一行是合计（商品页：想要、浏览、收藏的合计）。
- 1280px 宽时表格不能出现横向滚动：列多了先把次要字段并到商品名下面那行，或者两个值上下叠在一格里（比如日期在上、时分秒在下）。

## 状态标签

全站只有六种语气（`StatusPill`），商品、订单共用：

| 语气 | 样子 | 用在 |
|---|---|---|
| `action` 轮到我做 | 近黑实心白字，最显眼 | 待发货 |
| `warning` 等对方 | 浅琥珀底深字 | 待付款 |
| `negative` 出了问题 | 浅红底深红字 | 退款中 |
| `positive` 成了 | 浅绿底深绿字 | 在售、交易成功 |
| `neutral` 进行中或已结束 | 浅灰底 | 已卖出、已发货 |
| `outline` 不在了 | 只有灰边 | 不在主页、已关闭 |

买到的订单站在买家这边：待付款是 `action`（轮到我付），待发货是 `warning`（等卖家），已发货叫"待收货"。

新状态先归到这六种里，不加新颜色。不用紫色、靛蓝。

未读数这种"要处理的队列"用红底白字的小计数（会话列表、未读标签）。

## 提示、空状态、加载、出错

- **页面顶部提示**（`Callout`）：登录失效、风控熔断用 `negative`，保持登录快到期、风控提醒用 `warning`。
  浅底、同色细边、深字，右边放能解决问题的那个按钮。
- **整块没数据**（`EmptyState`）：一句话说清楚为什么没有、下一步做什么，必要时带按钮。不放插画、不放大图标。
- **一小块没内容**（`EmptyNote`，比如还没有改动记录）：保留块标题，虚线框里一句话。
- **加载中**（`RowsSkeleton`）：按真实行高画灰条，数据到了布局不跳；灰条只做慢慢的明暗变化，不用扫光渐变。
- **出错**（`LoadError`）：出现在出错的那一块里，"读取本地订单失败：原因"，带一个"重试"。不整页报错。
- **操作结果**：用 toast（页面上方居中），成功说做了什么（"同步完成：新增 1，更新 2"），失败说原因。

## 弹窗和抽屉

- 看详情用右侧抽屉（`Sheet`），最宽 512px；改价、确认删除用居中弹窗（`Dialog` / `AlertDialog`）。
  编辑商品（描述、图片、分类、邮费、发货地）是单独一页 `/items/:id/edit`，表单和发布页同一个。
- 危险操作（删除、提前解除熔断）用 `AlertDialog`，标题是问句，正文写清楚后果。
- 弹窗里的提醒（比如改价幅度太大）用和 `Callout` 一样的 `warning` 配色。
- 阴影只给浮起来的东西：菜单、弹窗、抽屉、提示。面板、卡片没有阴影。弹窗后面是 30% 的黑色遮罩，不做模糊。

## 交互和可访问性

照 Web Interface Guidelines 审过一遍（2026-10-31），定下这几条：

- **筛选放在网址里**：状态筛选用 `useUrlParam`（`?status=sold`、`?view=unread`），刷新、复制链接、前进后退都保持；
  默认值不写进网址。改网址里的一个参数时保留别的参数。搜索框的字不放进网址。
  例外是"搜索"页：搜的是闲鱼，搜索词和条件就是这一页要看的东西，点搜索时整组写进网址（`?q=…&sort=new&f=personal`），
  打字的时候不写。搜索页上面是"搜索结果 / 暂存"两个下划线标签（`?view=stash`），看暂存时不搜闲鱼；
  结果每行最右边是「暂存」开关（存了变"已暂存"，再点移出），暂存列表的行操作收在 `…` 里，移出后 toast 带"撤销"。
- **表单**：每个输入框都有 `<Label htmlFor>` 或 `aria-label`；输入框下面的提示和报错有 id，用 `aria-describedby` 连到输入框。
  一直在的提示行用 `aria-live="polite"`，出错才出现的那行用 `role="alert"`。改价、订单号这类输入框关掉 `autoComplete`，
  搜索框还关掉拼写检查。占位文字以"…"结尾。
- **金额**用 `yuan()`（`Intl.NumberFormat`，千位逗号，最多两位小数），数量用 `count()`，时间用 `format.ts` 里按北京时间的函数，
  不要自己拼字符串。
- **ID、订单号、账号**加 `translate="no"`，免得浏览器翻译把它们改乱。
- 只有图标的按钮要有 `aria-label`；能点的东西用 `<button>` 或链接，有 `focus-visible` 的焦点环，不要光写 `outline-none`。
- 动画只动颜色、透明度和位置，`transition` 写明属性，不用 `transition-all`。系统设置了减少动态效果时，全站动画停掉（`index.css`）。
- 超过 50 行的长列表（会话列表）每行加 `content-visibility: auto`；面板里自己滚动的区域加 `overscroll-contain`。
- `<img>` 写上宽高，屏幕外的图 `loading="lazy"`。

## 不做的事

渐变、毛玻璃（`backdrop-blur`）、发光、彩色圆圈里放图标的 KPI 卡、迷你走势图、彩虹色图表、表情符号、
标题上方的小标签、全大写加字间距的小字、深色或彩色的侧栏、紫色和靛蓝、整行彩色的提示条。

## 新页面检查

- [ ] 标题行有 h1 和一句说数据的说明；主按钮最多一个
- [ ] 每块都有标题；块和块之间 24px
- [ ] 同一个数只出现在一个地方
- [ ] 金额、数量右对齐、等宽数字；缺值 `-`，零是 `0`
- [ ] 状态用 `StatusPill` 的六种语气
- [ ] 有加载、空、出错（带重试）三种状态
- [ ] 筛选在网址里；输入框都有标签，报错连到输入框
- [ ] 只用键盘（Tab、方向键、Enter、Esc）能走完这一页的主要操作
- [ ] 1280、1440、1920 三个宽度都看过（taste 检查用 `inspect.mjs --widths 1280,1440,1920`）；1280 下表格不横向滚动
- [ ] 深色模式看过一遍
